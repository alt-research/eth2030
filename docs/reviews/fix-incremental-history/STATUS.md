# Incremental authenticated history and lazy point consumers

The audit measured 11,445 logical database reads to persist one changed account in an 8,192-account state and the same read count to open history. Keep the existing immutable content-addressed history schema but prepare only changed account/storage trie paths using the already pinned Geth generic trie library, backed by a Keccak-verifying native node/code adapter. Native EVM, journal, gas/fork rules and the independent full native-root controls remain intact. No new dependency, runtime feature switch or cryptographic exception is introduced.

Memory overlays track changed accounts/slots, including snapshot rollback and merged dirty storage. Newly generated immutable nodes/code remain owned by an unpublished view until the caller's existing atomic validated-block batch commits. A discarded batch can be retried without losing prepared nodes. Existing roots and code are not overwritten. Persistent native chains cache lazy root views after publication; explicit complete-memory simulators retain their type and preimages for differential consumers. Legacy complete-memory helpers keep an independently authenticated full-import fallback on a change-set mismatch, never on a corrupt-history read error.

OpenTrieHistory now resolves authenticated accessed paths rather than scanning unrelated state. AuditTrieHistory retains explicit complete-availability/code/storage validation for indexed startup and exclusive maintenance. Snap checkpoint adoption indexes its already authenticated full snapshot once and then uses a fresh lazy execution root; ordinary commits do not rewrite full flat snapshots. Explicit imports/exports, checkpoint range serving, complete audits and unindexed legacy replay remain whole-state operations by design. This correction qualifies steady indexed roots and point consumers, not unlimited mainnet capacity.

Point balance/nonce/code/storage/proof responses check lazy read errors; execution, builders and transaction admission reject unreadable accessed data. Chain execution classifies such failures as storage faults rather than consensus-invalid nonces/payloads. Proofs remain bound to the exact requested header root. Caller contexts propagate through native simulation/trace/access-list wrappers, while cached copies detach the originating request lifetime. Sparse metadata validation takes the exclusive existing pool lock because lazy reads populate a private mutable cache.

Regressions cover path-bounded one-account/one-slot work at increasing state sizes, independently native-verified roots and proofs, old-root isolation, snapshot rollback, failed publication/retry, accessed-content corruption through real HTTP and admission, cancellation/cache ownership and exported unpublished-code ownership.
