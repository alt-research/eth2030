# Exact hash-selected execution RPC contexts

The actual three-EL process campaign passed four signed application transactions and complete header/transaction/receipt commitments, then Native eth_call rejected EIP-1898 blockHash objects accepted by unchanged Geth. This correction implements the six EIP-1898 methods and shares exact-header selection with estimateGas, createAccessList, debug_traceCall and simulateV1. Unknown blocks return -32001 before canonical checks; known noncanonical selections with requireCanonical return -32000. Malformed and ambiguous selectors return -32602. Hashes are validated without truncation. Existing number/tag selectors remain supported.

Execution uses the selected header's frozen state and parent-linked ancestry, including retained orphan branches. Resolving a hash and then executing by its number is deliberately avoided. State/code overrides are isolated. Proofs are generated against the exact selected header root.

The actual HTTP/Engine regression imports two independently rehashed height-two branches with different withdrawal balances, restores one canonical branch and queries both. It verifies branch-specific BLOCKHASH in calls, estimates, access discovery and traces; independently verifies both account MPT proofs using unchanged Geth; checks overrides and unchanged canonical state; and exercises four selector failures across nine methods. All affected rpc/node packages pass. Three behavior mutations (canonical ancestry substitution, omitted canonical policy and dropped overrides) fail at the intended real-node assertions and are restored.
