# RPC execution cancellation in progress

The predeclared operating campaign exposed a source-level gap before pressure testing: both HTTP RPC dispatchers discard r.Context, batch requests create no request context, and ordinary native call/estimate/access-list execution has no context override. Simulate/trace construct bounded contexts from context.Background, so client cancellation does not release their remaining work. This is an execution-node request lifetime issue, not a consensus-rule change.

EIP-1474 JSON-RPC request/response and error semantics, EIP-1898 selectors and the selected EVM rules remain the authority for observable execution. Request cancellation is local transport metadata and must never become a JSON field, fork parameter or runtime feature switch. The intended correction binds an immutable request context to the existing native backend, preserves existing explicit trace/simulation limits, and propagates cancellation into existing EVM context support. Shared API maps/locks must not be copied. Actual HTTP and concurrent isolation evidence are required before claiming the operating cancellation gate.

The implementation carries local context through both actual HTTP servers and admitted batch items. A fresh native backend view owns the immutable context while retaining the same Node/Engine pointers. Only stateless execution handlers use that view; shared API maps, subscriptions and locks are not copied. Calls, estimates and access-list discovery retain gas/iteration bounds and share a five-second operation deadline, matching the unchanged Geth 1.17.10 default RPC EVM timeout. Existing trace option/simulation limits derive from the caller context. Queued batch work is not dispatched after cancellation, and response IDs/order remain intact.

Actual native EVM tests execute an isolated storage write followed by a high-gas loop, cancel during execution, require release and unchanged canonical state, and keep another request usable both concurrently and afterwards. Real TCP HTTP clients disconnect from simple, extended and batch servers; their actual EVM handlers release within the unchanged one-second observation bound. Pre-cancelled calls/estimates/access-list/traces/simulations avoid all Node state access. The first 100-million-gas control could naturally finish within one second and did not distinguish an erased context, so the call control now uses one billion explicit gas; the normal five-second operation bound remains in force. Three executed mutations erase backend binding, EVM context or batch transport context; each fails executed disconnect assertions, then sources are restored.

The added stronger concurrent-isolation assertion also passes the final affected race run. The initial full run caught the independently corrected profile allocation representation in PR 101; its original failure is retained. The fix does not claim WebSocket remote-close detection or interruptible historical disk/state replay; those request-lifetime boundaries remain explicit subsequent work. Runtime composition and pressure qualification remain pending.
