# WebSocket execution lifetime in progress

The actual Node WebSocket path reads one frame, executes it synchronously through a new background HTTP request, and only then reads again. Consequently, a remote close is not detected while execution is busy. PR 106 supplies native request context support; this review supplies the actual connection lifetime for WebSocket dispatch. EIP-1474 JSON-RPC messages and exact block/execution rules remain unchanged. Gorilla permits one reader and one writer concurrently; one bounded reader must continue observing close events without starting concurrent execution or copying shared API state.

The actual Node transport now uses one reader and one writer, forwards the connection context through its existing HTTP dispatcher, and cancels all active/queued work when the connection closes. Sixteen pending frames and the existing 1 MiB WebSocket message limit bound retained input; the existing write deadline bounds blocked responses. Normal queued requests preserve serial order and IDs. A single shared server constructor sets the parent context and registers its shutdown cancellation because http.Server.Shutdown does not itself close hijacked WebSockets. The tests use that same constructor, not a separate reproduction of its shutdown wiring.

Five actual native-node/Gorilla TCP tests pass: remote close with a queued frame; active/queued work after queue overflow; oversized frame while EVM execution is active; normal queued responses; and server shutdown of hijacked execution. A second concurrent connection remains usable and cancelled isolated storage writes never reach canonical state. Three executed mutations erase connection context, remove the actual factory shutdown hook or exceed the declared queue bound; each fails its executed test, then source bytes are restored and all real transport tests pass.

All 215 full package suites, 20 affected race suites, 44 tagged core/p2p integration suites, full vet and the native-node build pass. The affected actual transport tests also pass a targeted race run. This separate review depends on PR 106. JSON-RPC wire fields, origins, single-frame request dispatch, gas/fork rules and authentication routing remain as before; this change adds no runtime feature switch. The compatible runtime tuple and pressure/queue observations are still measured separately in PR 101.
