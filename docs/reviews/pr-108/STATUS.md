# Actual moving-head cold synchronization in progress

A fresh empty-database Native EL (8896b32b) peers with unchanged archival Geth, while a fresh validator-free Lighthouse checkpoint client imports the real live chain optimistically and drives actual Engine forkchoice targets. The EL repeatedly fetches independent headers/bodies but remains at genesis. Source tracing shows that every changed CL target cancels and discards the full backward ancestry walk before it can reach an execution-validated ancestor. The original no-peer/short-chain tests do not prove long moving-target progress. An explicit fixed-target causal control is retained separately and is not relabelled as an automatic moving-target pass.

EIP-3675 keeps target selection with the driving CL, and the selected Engine API keeps SYNCING until execution is actually validated. The correction must preserve immediate replacement/stop cancellation, keep all staged data separate from chain validation/canonical publication, and bound both header count and body bytes. Existing go-ethereum LRU implementations are preferred over a new cache framework. No runtime switch or consensus-rule relaxation is introduced.
