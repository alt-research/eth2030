# Status

Implementing current ProgressiveContainer(active_fields) semantics from EIP-7495 with EIP-7916 progressive Merkleization. The audit reproduced 477 incorrect mixed-root gindices in 487 progressive-list proof cases; correcting the root-prefix in the diagnostic makes all 487 verify. Four old conformance tests also accepted ordinary binary Merkleization in a temporary mutant copy. These are retained as pre-fix failures rather than counted as completed validation.

The new API will own an immutable schema, reject illegal type layouts and reuse existing canonical Container serialization. The old optional-field root utility will be explicitly deprecated as a compatibility helper; it will not serve as a ProgressiveContainer type declaration. Existing production EL/CL roots and wire formats must remain independently equal.

Implemented immutable validated schemas, canonical offsets/codecs, field proofs and the shared mix-in gindex repair. Existing execution payload/transaction SSZ hashing now validates slot masks and propagates errors without changing its independent reference roots. 29 unchanged-remerkleable container cases, 1016 field branches, 487 list proofs and four illegal schemas pass. A separate unchanged consensus reference validates the actual 384-validator Gloas state: identical serialized-byte fingerprint, all 46 field roots/branches and original current/next/finalized proofs. It also confirms normative 256-position layouts without the extra field-name restriction imposed by remerkleable. The unchanged CL captured consumer passes its release integration test. Full suites and executed rejection mutations remain in progress.
