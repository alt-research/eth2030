The incoming head/safe/finalized headers are independently canonical in both clients. The prior successful unfinalized head is explicitly unavailable in Geth and is not counted as an agreed header. All available complete headers independently rehash correctly and common header RLP bytes agree.

For attributes-free notifications only, the production backend now uses Engine Paris forkchoice rule 2's permitted ancestor skip when a validated canonical ancestor notification predates durable finality. It returns VALID with that nominated latestValidHash and no payload ID. The serialized check reads state only. It rejects unknown, noncanonical or above-head checkpoints and invalid safe/finalized ordering; it does not lower the durable head, safe/finalized state, execution root, transaction-pool context or finalized guard. Ordinary forward publication and actual build/reorg rules remain with the atomic forkchoice path.

Actual HTTP tests on Osaka and Amsterdam build and independently rehash a canonical chain plus a side branch, finalize, close/reopen the Node database, send two stale canonical notifications and verify unchanged persisted finality/head/root. Six invalid checkpoint/branch controls per fork remain rejected, and a subsequent ordinary payload still advances normally. A separate original-wire test binds the captured failure to unchanged Geth header commitments; it is observation verification, not a claimed full replay of the long original state. Affected chain/backend/Engine tests pass. Three restored behavior mutations are detected; the initial compile-failing mutant is excluded.
