# EIP-7954 limit implementation evidence

Base: origin/master `38ea9259`; branch: `feat/glamsterdam-contract-limits`. Specification: EIP-7954 at EIPs `3db38a3725105cb67b8804ac3e147967113bc3ca`. Local refs retain an older 32/64 KiB draft and were not modified.

- Published 64/128 KiB limits are selected by the existing fork rules; no new switch is introduced.
- Actual CREATE and CREATE2 tests accept 65,536-byte runtime and 131,072-byte initcode; reject limit+1 at the intended size checks. A PUSH3 test payload avoids truncating 65,536 to zero.
- Native transaction tests reject oversized initcode as an invalid transaction, with nonce/balance/gas-pool unchanged. They accept exact-limit STOP initcode. Pool tests check the same boundaries and avoid the previous encoded-size-policy rejection of an otherwise valid 128 KiB input.
- The encoded-envelope policy expands only for post-fork creation transactions; ordinary transaction data and pre-fork policy stay bounded as before.

Before the fix, the new VM tests failed with max code/initcode size errors at the valid published limits. Native over-limit transactions incorrectly returned an included execution failure; the pool admitted pre-fork oversized input and rejected the valid new maximum because of envelope size. All targeted assertions passed after the fix.

All passed. No official independent-client, live network, or new complete gas-model qualification is claimed. Existing later-fork Frame tests are included in the affected suites. The older 8037/8038 pricing and RPC estimation semantics are separately tracked and must be qualified before the complete Glamsterdam release.
