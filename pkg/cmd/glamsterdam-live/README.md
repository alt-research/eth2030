# Live native/independent application commitment campaign

This command consumes the 31 signed transaction and 17 getter sequence qualified at source 3dc08a93, preserves complete application/authorization fields, and re-signs only the outer envelopes with appropriate live fee caps. It uses the disposable preloaded private-network key 1, plus the original key-2 authorization tuples. It refuses other chain IDs or a different expected genesis, records every actual RPC request/response and duration into a new trace file, and uses a bounded overall deadline.

Supply at least two real EL endpoints (the intended campaign uses independent Geth plus two native ETH2030 nodes), the exact generated private genesis hash and a fresh output path. It waits for all actual ELs to import Amsterdam headers, submits the same signed bytes to all pools, verifies actual receipts and reconstructs each complete header, transaction trie and receipt trie independently using unchanged Geth types. Receipt metadata is bound to the requested block and exact transaction positions. A previously propagated transaction is accepted only after recovering that exact transaction hash from the receiving endpoint. Historical getter calls use the exact canonical block hash; actual getter bytes must agree and match the qualified application semantics. Pair reserve timestamps are compared across real nodes, while only reserve values are compared to the isolated fixture's different timestamp context.

The final transaction carries a real blob, its commitment and all 128 version-1 cell proofs. Failure exits nonzero and preserves complete prior evidence. Unit/race controls cover malformed response identity/errors, tampered complete header claims, requested block identity, actual transaction/receipt roots, complete re-signing fields and rejection of non-test chains before publication.

This command alone does not prove external builder selection, beacon-envelope lifecycle, Engine wire traces, recovery, peer loss or operating budgets. Those are separate campaign controls and stay open until actually observed. Do not use a matching execution hash as a substitute for the actual roots, receipts and imported beacon observations.

Receipt polling records temporary fork selections and waits under the existing overall deadline until every endpoint identifies the same canonical execution block. Only then are status, gas, effective price and logs compared and the full header/transaction/receipt commitments reconstructed. The first live attempt exposed normal reorg convergence, and its original per-node receipts are retained; same-block inconsistencies still fail immediately.

The `factory` scenario checks EIP-7997 at the pinned EIPs revision using the actual genesis account at 0x4e59b44847b379578588920cA78FbF26c0B4956C. It verifies exact code/nonce, the unpadded 20-byte CREATE2 return and absence of simulation side effects, then submits success, collision and short-salt transactions with expected statuses 1/0/0. All three endpoints must agree on full block/receipt commitments, deployed code, forwarded value, creator/caller nonces and getter bytes. Six final account proofs are captured for the separate independent ledger consumer. The input salt is fixed; use a fresh private genesis for another publication run, preserving the original trace.
