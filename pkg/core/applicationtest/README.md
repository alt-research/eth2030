# Published application sequence qualification

Run `go test -json -count=1 ./core/applicationtest` from `pkg`. No live RPC, compiler, package registry, environment variable or oracle replacement is required. CI retains the complete signed transaction bytes, native/independent post-state roots, receipt gas, block dimensions, emitted logs and actual getter outputs.

`testdata/sources.json` pins six verbatim published artifacts: Uniswap V2 core 1.0.1 ERC20/factory/pair and Safe contracts 1.4.1 Safe/proxy/MultiSend. The original archives were verified against npm SHA-512 integrity, and exact member SHA-256 values are checked by default tests. The original package licenses are retained beside the fixtures. The artifacts are deployed with their published creation code, rather than substituted or hand-written runtimes.

The Osaka/Amsterdam sequences independently decode the same real signed bytes, execute native ordinary transactions and unchanged Geth v1.17.10, and compare complete roots, logs, status and paid gas at every step. Amsterdam execution/state block dimensions are also compared. Getter calls compare actual return bytes and assert business outcomes. Checks include factory CREATE2 addresses, liquidity mint/swap/burn, duplicate/insufficient-balance failure, Safe ownership/proxy/DELEGATECALL, bounded forwarding, successful/failed MultiSend, temporary approvals across sibling calls without an initial reservoir, nested rollback, wallet refund/fee conservation and EIP-7702 Safe authorization/operation/revocation.

The actual Safe/token child succeeds at 30,000 forwarded execution gas and fails at 15,000 on both selected forks. On Amsterdam the successful call's state gas alone exceeds its forwarded execution budget, proving a real reservoir consumer. Repriced cold accesses mean a guessed 15k/20k/25k success cannot be inferred from synthetic SSTORE costs. Those initial failed assumptions are excluded from qualification. The temporary-approval sequences use a 1M top-level limit below the execution cap, so their LIFO refill/rollback does not start with a reservoir.

This is a persistent application state-transition sequence with independently recorded block contexts, not a pool/Engine/header-validation or full-process beacon-network campaign. Base fee is fixed at one for the isolated transition comparison; real fee recurrence, system transitions, forkchoice and processes are qualified separately. It preserves the selected merged EIP-8037 model, including its documented GAS attribution limitations, without silently adopting open alternatives.
